# راهنمای کامل پیاده‌سازی DubFlow

> این سند پیاده‌سازی طرح [`dubflow-plan-b-fa.md`](dubflow-plan-b-fa.md) را توضیح می‌دهد: ساختار کد، فرمت داده‌ها، اجرای مرحله‌به‌مرحله روی سرور GPU، پیکربندی‌ها، منابع لازم، تست‌ها، و محدودیت‌های شناخته‌شده.

---

## ۱. خلاصه

| | DubFlow-M (کیفیت) | DubFlow-S (سرعت) |
|---|---|---|
| بک‌بون | DiT با ۲۴ لایه، ‏d=1280، skipهای U-ViT، attention محلی و سراسری | U-Net چندنرخی (۲۵ → ۱۲٫۵ → ۶٫۲۵ → ۱۲٫۵ → ۲۵ هرتز)، ‏d=768 |
| پارامترها (بدون VAE) | **۸۱۵M** (بک‌بون ۷۵۱M، متن ۴۰M، تیمبر ۱۰M) | **۱۹۸M** (بک‌بون ۱۷۰M، متن ۱۹M) |
| DubVAE (مشترک) | ۱۶۸M (انکودر ۵۱M و دیکودر ۱۱۷M) | همان |
| پیکربندی | `configs/dubflow_m.yaml` | `configs/dubflow_s.yaml` |

اعداد بالا با `dubflow-params` از خود کد محاسبه شده‌اند.

**ایدهٔ اصلی:** مدل یک صحنه (تا ۶۰ ثانیه) را یکجا تولید می‌کند. هویت و لحن **هر لحظه** از **همان لحظهٔ صدای اصلی** گرفته می‌شود (TSVB). هیچ برچسب گوینده و هیچ دیاریزیشنی وجود ندارد. متن ترجمه به‌صورت «قطعه‌های زمانی» می‌آید و توکن‌های هر قطعه یکنواخت روی بازهٔ زمانی همان قطعه پخش می‌شوند (average upsampling لنگرشده).

## ۳. نصب

```bash
git clone <repo> && cd dub
bash scripts/00_setup.sh          # venv، نصب وابستگی‌ها، اجرای تست‌ها
```

- **نیازمندی‌ها:** پایتون ۳٫۱۰ یا بالاتر، PyTorch ۲٫۳ یا بالاتر با CUDA.
- **وابستگی‌های اختیاری** (`.[features]`): ‏`transformers` (برای WavLM-SV، w2v-BERT 2.0 و Whisper)، `funasr` (برای emotion2vec)، `speechbrain` (برای ECAPA، اختیاری).
- **هم‌ترازی کلمه‌ای فارسی:** `pip install uroman`.
- **دانلود مدل‌ها:** در اولین اجرا خودکار انجام می‌شود (HuggingFace و ModelScope). اگر سرور اینترنت ندارد، پوشه‌های `~/.cache/huggingface` و `~/.cache/modelscope` را از یک ماشین دیگر کپی کنید.

## ۴. فرمت داده‌ها

### ۴.۱ مانیفست پیش‌آموزش (`data/pretrain_manifest.jsonl`)، یک خط برای هر گفتار

```json
{"id": "en_000123", "audio": "/data/en/000123.wav", "lang": "en", "speaker": "spk_42",
 "text": "hello there", "words": [{"w": "hello", "s": 0.12, "e": 0.48}, {"w": "there", "s": 0.55, "e": 0.90}]}
```

- `lang` یکی از `en`، `fa`، `zh` یا `other` است. **متن چینی باید pinyin با شمارهٔ لحن باشد** (مثلاً با `pypinyin`).
- `words` اختیاری است، ولی **به‌شدت توصیه می‌شود**، چون مرز قطعه‌ها از آن ساخته می‌شود. اگر ندارید: `python -m dubflow.preprocess.align --manifest in.jsonl --out out.jsonl` (MMS_FA، با uroman برای فارسی).
- `speaker` برای انتخاب شریک hard-negative در صحنه‌های مصنوعی استفاده می‌شود. اگر نباشد، `id` به جای آن استفاده می‌شود.

### ۴.۲ مانیفست VAE (`data/vae_manifest.jsonl`)

فقط `{"id", "audio"}` لازم است. هر گفتاری مناسب است. مقداری صدای غیرگفتاری هم اضافه کنید (خنده، نفس، فریاد).

### ۴.۳ فیلم‌های دوبله (`data/films.tsv`)

هر خط: `film_id <TAB> vocals_en.wav <TAB> vocals_fa_vc.wav <TAB> script_fa.json|srt`

- هر دو فایل صوتی **وکالِ جداشده** (بدون موسیقی و افکت) و **روی یک timeline** هستند.
- تراک فارسی همان **نسخهٔ VC‌شده به صدای بازیگر اصلی** است.
- اسکریپت (JSON یا SRT):
  ```json
  {"chunks": [{"t0": 12.40, "t1": 14.10, "text": "متن فارسی با کسرهٔ اضافهِ لازم", "ok": true}]}
  ```
  `ok: false` یعنی VC آن خط خراب است. آن خط فقط context می‌شود و loss نمی‌گیرد.

### ۴.۴ اسکریپت استنتاج (خروجی مترجم بیرونی)

```json
{"lang": "fa",
 "chunks": [{"t0": 12.40, "t1": 14.10, "text": "<emph>واقعاً</emph> رفتی؟", "stream": 0},
            {"t0": 14.10, "t1": 15.30, "text": "آره <laugh>", "stream": 0}]}
```

- **واحد، قطعهٔ زمانی است، نه خط زیرنویس.** قطعه‌ها را روی مکث‌های متن اصلی بشکنید.
- **تگ‌های پشتیبانی‌شده:** `<emph>…</emph>`، `<whisper>…</whisper>`، `<shout>…</shout>`، `<laugh>`، `<breath>`، `<sigh>`، `<cry>`، `<cough>`، `<gasp>`، `<scream>`، `<pause>`، `<hum>`.
- **اعداد را با حروف بنویسید.** کسرهٔ اضافه (ِ) و مصوت‌های مبهم را بگذارید.
- **`stream` اختیاری است.** اگر دو خط در زمان هم‌پوشانی داشته باشند (دو نفر هم‌زمان حرف بزنند)، خط دوم خودکار به جریان ۱ می‌رود. اگر خودتان `stream` بدهید و تداخلی در یک جریان نباشد، همان حفظ می‌شود. حداکثر **دو** گفتار هم‌زمان پشتیبانی می‌شود (بخش ۱۰-الف).

## ۵. اجرای مرحله‌به‌مرحله

پیش‌فرض‌ها در `scripts/env.sh` تنظیم می‌شوند (تعداد GPU، پیکربندی، backendها). برای مدل S:

```bash
export CFG=configs/dubflow_s.yaml RUN=runs/s
```

| # | دستور | خروجی | توضیح |
|---|---|---|---|
| D0 | `bash scripts/10_train_vae.sh` | `runs/vae/last.pt` | ۲۰ هزار گام اول فقط بازسازی است، بعد GAN فعال می‌شود |
| — | `bash scripts/20_extract_pretrain.sh` | `feats/pretrain/*.pt`، ‏`*.aug<k>.pt`، ‏`index.pt`، ‏`latent_stats.pt` | به ازای هر GPU یک shard. با `--skip-existing` قابل ادامه است. نسخه‌های تخریب‌شده با `AUG` (پیش‌فرض ۲) |
| D1 | `bash scripts/30_train_d1.sh` | `runs/m/d1/last.pt` | REPA تا گام ۲۰۰ هزار فعال است. `--vae` لازم است (برای overlap مصنوعی) |
| — | `bash scripts/40_build_dub.sh` | `data/dub/pairs.jsonl`، ‏`feats/dub_src`، ‏`feats/dub_tgt` | ردّ کوتاه‌پنجرهٔ واقعی و نسخه‌های تخریب‌شده فقط برای سمت مبدأ ساخته می‌شوند |
| D2 | `bash scripts/50_train_d2.sh` | `runs/m/d2/last.pt` | آمار نرمال‌سازی latent از D1 به ارث می‌رسد |
| D3 | `bash scripts/60_train_d3_grpo.sh` | `runs/m/d3/last.pt` | برای پاداش CER: ‏`grpo.asr_model=<whisper فارسی>` |
| D4 | `bash scripts/70_distill.sh` | `runs/m/d4/last.pt` | M→S: ‏`STUDENT_CFG=configs/dubflow_s.yaml` |
| دوبله | `bash scripts/80_dub.sh vocals_en.wav script_fa.json out.wav me.wav` | wav ‏۲۴ کیلوهرتز | با student، ۴ گام و بدون CFG |

**نکات:**
- **ادامهٔ آموزش (resume):** کافی است همان دستور را دوباره اجرا کنید. `last.pt` در `train.out_dir` خودکار بارگذاری می‌شود.
- **override تنظیمات:** هر کلیدی از پیکربندی را می‌شود از خط فرمان عوض کرد، مثلاً `train.lr=5e-5 data.max_frames=1000`.
- **نمونه‌های صوتی در طول آموزش:** با `--vae` در `train_dubflow`، در هر ذخیره یک فایل در `samples/` نوشته می‌شود.
- **لاگ‌ها:** در `train_log.txt` و TensorBoard (`tb/`).
- **نویز و موسیقی واقعی برای augmentation (توصیه‌شده):** `export NOISE_LIST=data/noise.jsonl MUSIC_LIST=data/music.jsonl` (هر خط `{"audio": path}`؛ مثلاً MUSAN، و استم‌های موسیقی و افکت فیلم‌ها). بدون آن‌ها نویز رنگی مصنوعی استفاده می‌شود. مقدار `AUG` باید با `data.src_aug_versions` یکی باشد.

## ۶. پیکربندی‌های مهم

| کلید | معنا |
|---|---|
| `model.tracks.*` | ابعاد ردّها. **باید با backend استخراج یکی باشد** (WavLM-SV ‏۵۱۲، ECAPA ‏۱۹۲، emotion ‏۶۴). اگر نباشد، آموزش با پیام خطای واضح متوقف می‌شود |
| `model.timbre.window_half` | نیم‌پهنای پنجرهٔ تیمبر (۲۵ = ±۱ ثانیه) |
| `model.cfg_dropout` | احتمال حذف هر شرط برای CFG |
| `data.lang_weights` | upsampling زبان‌ها (پیش‌فرض: فارسی ×۶) |
| `data.scene_p`، `hard_negative_p`، `no_gap_p`، `cross_speaker_chunk_p` | ساخت صحنه‌های مصنوعی و حالت‌های سخت |
| `data.window_min_offset_sec` | حداقل فاصلهٔ offset-window (۳ ثانیه) |
| `data.overlap_p`، `overlap_min_sec`، `overlap_max_sec` | احتمال و طول overlap مصنوعی در پیش‌آموزش (پیش‌فرض ۰٫۱۵، ۰٫۲ تا ۱٫۵ ثانیه). اگر بیشتر از صفر باشد، D1 به `--vae` نیاز دارد |
| `data.ctx_p`، `ctx_min_sec`، `ctx_max_sec` | احتمال و طول پیشوند شناخته‌شده (context) در آموزش (۰٫۳؛ ۰٫۵ تا ۴ ثانیه) |
| `data.src_aug_p`، `src_aug_versions` | احتمال شرط‌گرفتن از نسخهٔ تخریب‌شدهٔ مبدأ، و تعداد نسخه‌ها (۰٫۵ و ۲). با `src_aug_versions=0` خاموش می‌شود |
| `model.context.enabled` | کانال context (پیوستگی صحنه‌ها) |
| `sample.context_sec` | طول context از صحنهٔ قبلی در استنتاج (۳ ثانیه؛ صفر یعنی خاموش) |
| `sample.guidance` | ضرایب CFG در استنتاج teacher (پیش‌فرض: all برابر ۱٫۵، timbre برابر ۰٫۵) |
| `grpo.*` | اندازهٔ گروه، پنجرهٔ SDE، وزن پاداش‌ها و gateها |
| `distill.*` | تعداد گام student، زیرگام‌های teacher، و احتمال تمرین یک‌گامی |

## ۷. منابع و زمان (تخمین)

| | M | S |
|---|---|---|
| VRAM استنتاج | حدود ۴ تا ۶ GB (به‌علاوهٔ مدل‌های ویژگی، حدود ۲ تا ۳ GB) | حدود ۲ تا ۳ GB |
| آموزش | کارت ۴۰ تا ۸۰ GB پیشنهاد می‌شود. با `activation_checkpointing` روی ۲۴ GB هم ممکن است، ولی batch کوچک | روی ۲۴ GB (3090 و 4090) راحت |
| D1 روی ۸ کارت H100 | حدود ۱ تا ۲ هفته | چند روز |

**اندازه‌گیری روی CPU** (۴ هستهٔ CPU، صحنهٔ ۳۰ ثانیه‌ای، صرفاً برای اثبات اجرا):
- یک گام کامل آموزش S (forward و backward): ۹٫۳ ثانیه، با پیک حافظهٔ ۲٫۷ GB
- یک گام ODE مدل M: ۶٫۸ ثانیه، با پیک حافظهٔ ۵٫۵ GB

روی GPU این زمان‌ها چند ده برابر کمتر است.

**فضای دیسک feature cache:** برای هر ساعت گفتار حدود ۱۲ MB برای latent، به‌علاوهٔ ردّها (fp16). برای ۵۰ هزار ساعت، حدود **۶۰۰ تا ۸۰۰ GB**. REPA آنلاین حساب می‌شود و چیزی ذخیره نمی‌کند.

- آموزش واقعی تا همگرایی
- bf16 و NCCL روی GPU
- کیفیت صوتی نهایی

**قبل از آموزش اصلی:** آزمایش‌های G1 تا G7 طرح را روی مقیاس کوچک اجرا کنید.

## ۹. عیب‌یابی

| نشانه | علت و راه‌حل |
|---|---|
| `model.tracks.X=... but feature cache has ...` | backend استخراج با پیکربندی نمی‌خواند. یا `model.tracks` را اصلاح کنید یا backend را |
| OOM در D1 | `train.batch_size` یا `data.max_frames` را کم کنید، و `train.activation_checkpointing=true` بگذارید |
| loss ‏REPA صفر یا ثابت | `repa_teacher.until_step` تمام شده، یا `wav` در batch نیست (فیلد `audio` مانیفست را چک کنید) |
| صدای دوبله صدای اشتباه است | ردّها در اجرای `extract` برای سمت مبدأ با `--short-window` ساخته شده باشند |
| در GRPO، مقدار reward همیشه منفی است | gateها برای مدل فعلی سخت‌اند. `grpo.gates.boundary` را موقتاً بیشتر کنید (هنوز سیگنال یادگیری دارد) |
| گفتار از قطعه بیرون می‌زند | زمان‌بندی مترجم را چک کنید (`t0` و `t1`). در استنتاج `--max-scene-sec` را کم نکنید |

## ۱۰. تفاوت‌های پیاده‌سازی با طرح (صادقانه)

1. **بک‌بون S یک «U-Net چندنرخی الهام‌گرفته از Zipformer» است، نه Zipformer کامل** (BiasNorm، SwooshR، NLA و ScaledAdam پیاده نشده‌اند). bypassهای یادگرفتنی و پردازش چندنرخی حفظ شده‌اند. **بهینه‌ساز هر دو مدل AdamW است.** Muon و ScaledAdam برای آزمایش G4 گذاشته شده‌اند.
2. **discriminator‌های VAE** MPD و STFT چندرزولوشنی هستند (به جای CQT-D).
3. **تخمین F0 داخلی** مبتنی بر autocorrelation است. برای ردّ لحن درشت (۵ هرتز) کافی است. اگر لازم شد، RMVPE یا PENN را در `utils/audio.estimate_f0` جایگزین کنید.
4. **VAD داخلی** انرژی‌محور است. برای صدای جداشده کافی است. Silero را می‌شود در `utils/audio.energy_vad` جایگزین کرد.
5. **هم‌پوشانی گفتار:** طرح، استخراج صدای هر نفر با سرنخ متن را پیشنهاد کرده بود. پیاده‌سازی ساده‌تر است: صدای مخلوط جدا نمی‌شود، و هویت صدای دوم (جریان ۱) از **بخش‌های تک‌نفرهٔ همان خط** گرفته می‌شود (بخش ۱۰-الف). اگر خط دوم هیچ بخش تک‌نفره‌ای نداشته باشد، از embedding مخلوط استفاده می‌شود. حداکثر دو گفتار هم‌زمان پشتیبانی می‌شود.
6. **مسیر جایگزین mel به‌علاوهٔ vocoder** (fallback در صورت شکست G1) پیاده نشده است. فقط DubVAE.
7. **اتاق مصنوعی:** تطبیق reverb با یک RIR مصنوعی (دنبالهٔ نمایی با میرایی وابسته به فرکانس) انجام می‌شود، نه با RIR واقعی تخمین‌زده‌شده. بازتاب‌های اولیه و رنگ دقیق اتاق بازسازی نمی‌شوند، فقط سطح و زمان دنباله.

## ۱۰-الف. چهار بهبود: هم‌پوشانی، پیوستگی صحنه‌ها، تطبیق آکوستیک، augmentation

### ۱) گفتار هم‌پوشان (overlap)

- **آموزش (D1):** با احتمال `data.overlap_p`، در یک تغییر گوینده نفر دوم **قبل از تمام‌شدن گفتار نفر اول** شروع می‌کند (۰٫۲ تا ۱٫۵ ثانیه هم‌پوشانی، حداکثر نیمی از گفتار نفر اول). صدا در **سطح موج** جمع می‌شود، چون latent مخلوط با جمع latentها برابر نیست. trainer همان صحنه را **آنلاین با VAE منجمد** دوباره encode می‌کند (`reencode_overlaps`). به همین دلیل D1 به `--vae` نیاز دارد؛ اگر نباشد، با پیام واضح متوقف می‌شود.
- **جریان‌ها:** `assign_streams` خطوطی را که در زمان هم‌پوشانی دارند به جریان‌های متفاوت می‌برد (حریصانه، به ترتیب شروع). همین تابع در پیش‌آموزش، D2 و استنتاج استفاده می‌شود.
- **ردّ جدید `spk_overlap`:** روی کل بازهٔ خطِ جریان ۱ که با خط دیگری هم‌پوشان است، هویت صدای دوم قرار می‌گیرد. این هویت از ردّ کوتاه‌پنجره روی **فریم‌هایی که آن خط تنها گفته می‌شود** (ترجیحاً ≥ ۰٫۵ ثانیه دور از ناحیهٔ هم‌پوشان) میانگین گرفته می‌شود. ستون overlap ردّ فعالیت هم روی فریم‌های هم‌پوشان ۱ می‌شود. ترتیب ردّها در `tracks.TRACK_ORDER` ثابت است و مدل ترتیب `model.tracks` را بررسی می‌کند.
- **آزموده‌شده:** تخصیص جریان (حفظ جریان معتبر، تداخل، سه خط هم‌زمان، محدودکردن شماره)؛ مقدار دقیق `spk_overlap` و پرچم overlap؛ re-encode (فقط آیتم‌های علامت‌خورده، با padding دست‌نخورده، و `src_latent` برابر `x1`)؛ دیتاست با `overlap_p=1` (wav مخلوط، پرچم، متن روی جریان ۱)؛ و دوبله با یک خط قطع‌کننده بدون `stream`.

### ۲) پیوستگی بین صحنه‌ها

- **مدل:** یک کانال ورودی `ctx_proj` روی `[latent شناخته‌شده، پرچم]` با مقداردهی صفر (روی checkpointهای قبلی بی‌اثر است).
- **آموزش:** با احتمال `data.ctx_p`، پیشوندی ۰٫۵ تا ۴ ثانیه‌ای از هدف به‌عنوان context داده می‌شود و از loss حذف می‌شود. نیمی از مواقع متن خطوطی که کاملاً داخل پیشوند هستند حذف می‌شود، چون در استنتاج هر دو حالت پیش می‌آید.
- **نمونه‌برداری:** فریم‌های شناخته‌شده در هر گام روی درون‌یاب داده قرار می‌گیرند (`(1-t)·x0 + t·ctx`) و در پایان دقیقاً برابر context هستند. در تقطیر هم teacher همین قاعده را رعایت می‌کند. GRPO بدون context اجرا می‌شود.
- **استنتاج:** پنجرهٔ هر صحنه `sample.context_sec` (۳ ثانیه) زودتر شروع می‌شود و آن فریم‌ها برابر latent تولیدشدهٔ صحنهٔ قبل قرار می‌گیرند. فقط بخش خود صحنه نوشته می‌شود. دیکودر VAE هم context سمت چپ را می‌بیند. با `--context-sec 0` خاموش می‌شود.
- **آزموده‌شده:** نگه‌داشتن دقیق فریم‌های context و اثرشان روی بقیه (هر دو بک‌بون)؛ گرادیان به `ctx_proj`؛ عدم ورود فریم‌های context به loss؛ هدف teacher در تقطیر؛ و در `dub()` اینکه هر صحنه دقیقاً با ۲۵ فریم پایانی صحنهٔ قبلی شروع می‌شود.

### ۳) تطبیق آکوستیک با صدای اصلی (EQ و reverb)

- **EQ:** طیف میانگین بلندمدت (LTAS) گفتار در باندهای ⅓ اکتاو مقایسه می‌شود و یک EQ هموار اعمال می‌شود: کاهش تا ۲۴ dB (برای صدای اصلیِ کم‌باند یا تیره)، افزایش حداکثر ۹ dB (تا نویز تقویت نشود). RMS کل حفظ می‌شود. مرجع ساکت یا تقریباً ساکت هیچ تغییری ایجاد نمی‌کند.
- **Reverb:** دو آماره به‌صورت کور از گفتار تخمین زده می‌شود. اول، نرخ تندترین افت‌های انرژی (اتاق اجازهٔ افت سریع‌تر را نمی‌دهد). دوم، سطح انرژی ۵۰ تا ۱۵۰ میلی‌ثانیه بعد از پایان عبارت‌ها. اگر صدای اصلی پُرانعکاس‌تر باشد، `(RT60, wet)` با جستجوی شبکه‌ای و **analysis-by-synthesis** طوری انتخاب می‌شود که آماره‌های دوبله برابر اصلی شوند. همان تخمین‌گر روی هر دو طرف اعمال می‌شود، پس خطای مطلق آن خنثی می‌شود. هرگز reverb کم نمی‌شود: اگر اصلی خشک باشد یا دوبله از قبل پُرانعکاس‌تر باشد، کاری انجام نمی‌شود.
- **در `dub()`:** برای هر صحنه، اگر گفتار کافی برای اندازه‌گیری نباشد، از آمار کل فیلم استفاده می‌شود. ترتیب: بلندی هر خط، سپس EQ، سپس اتاق. دنبالهٔ reverb (تا ۱ ثانیه) به صحنهٔ بعد overlap-add می‌شود و قطع نمی‌شود. با `--no-acoustic-match` خاموش می‌شود. هزینه حدود ۰٫۸ ثانیه CPU برای هر ۱۰ ثانیه صدا است.
- **اندازه‌گیری روی سیگنال مصنوعی:** فاصلهٔ LTAS از ۶٫۱ به ۱٫۲ dB (صدای روشن‌تر) و از ۷٫۱ به ۰٫۹ dB (صدای تیره‌تر) رسید. برای سه اتاق (RT60 برابر ۰٫۳، ۰٫۶ و ۱٫۰ ثانیه)، سطح دنبالهٔ دوبله از حدود ۴۹- dB به فاصلهٔ کمتر از ۱٫۵ dB از اصلی رسید.

### ۴) augmentation سمت مبدأ در آموزش

- **مشکل:** در استنتاج، صدای اصلی وکال جداشدهٔ فیلم است (نویز، نشت موسیقی، reverb، آرتیفکت جداسازی)، ولی دادهٔ پیش‌آموزش تمیز است.
- **راه‌حل:** `extract --augment N` برای هر آیتم N نسخهٔ تخریب‌شده می‌سازد (`<id>.aug<k>.pt`) با زنجیرهٔ تصادفی از این موارد: reverb، موسیقی و افکت (SNR از ۸ تا ۳۰)، نویز (۱۰ تا ۳۵)، آرتیفکت جداسازی، EQ، محدودیت باند و clipping. این زنجیره برای هر آیتم و هر نسخه تکرارپذیر است.
- **در آموزش:** با احتمال `src_aug_p`، **فقط سمت شرط** (latent مبدأ برای پنجرهٔ تیمبر، و ردّهای هویت، لحن، احساس و فعالیت) از نسخهٔ تخریب‌شده خوانده می‌شود. **هدف همیشه تمیز است.** نسخه‌های تخریب‌شده وارد آمار latent و index نمی‌شوند.
- **آزموده‌شده:** تکرارپذیری و تنوع زنجیره، طول ثابت، و حد پیک؛ ساخت فایل‌ها با همان تعداد فریم؛ اینکه در دیتاست `x1` دست‌نخورده می‌ماند و `src_latent` تغییر می‌کند؛ و هشدار در صورت نبودن فایل‌ها.

**نکته:** هر DataLoader worker حالا جریان تصادفی خودش را دارد. قبلاً همهٔ workerها کپی یکسانی از `random.Random` داشتند و تصمیم‌های تصادفی‌شان (ساخت صحنه، augmentation و context) هم‌بسته بود.

## ۱۱. مسیرهای توسعهٔ بعدی

- overlap بیش از دو نفر، و استخراج صدای هر نفر با سرنخ متن
- تخمین RIR واقعی (بازتاب‌های اولیه) برای تطبیق دقیق‌تر اتاق
- Muon، ScaledAdam، و MeanFlow از صفر (آزمایش‌های G4)
- Reward Model ترجیح انسانی برای GRPO
- streaming با پنجره‌های صحنه و دیکودر causal
